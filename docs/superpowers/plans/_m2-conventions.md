# M2 共用实现约定（四份游戏计划都适用）

这些条目是执行 M2 期间实测发现的**跨任务口径**，写在这里一次，四份计划（`2026-10-18-m2-1-stroop.md`、`2026-10-19-m2-seqmem.md`、`2026-10-19-m2-mot.md`、`2026-10-19-m2-gestalt-b.md`）的测试夹具与注册任务都按这里执行。计划正文若与本文件冲突，以本文件为准（本文件每条都带实测出处）。

## F-1 帧序列夹具不许用浮点累加计数器

**症状**：计划里的喂帧夹具写成

```ts
for (let t = from; t <= to; t += stepMs) engine.tick(t);
```

当 `from` 是真实 rAF 量级（`1.7e12`）而 `stepMs = 16` 时，`1.7e12` 附近的 `ulp ≈ 0.000244`，累加误差让末帧落到 `6999.99999988` 这类值，`t <= to` 提前为假 → **永远喂不到运动/曝光结束的那一帧**，「长间隔作废」类用例首跑必红，且红的原因和断言毫无关系。

**规定的写法**：整数下标算时间，别累加浮点。

```ts
const n = Math.floor((to - from) / stepMs);
for (let i = 0; i <= n; i++) engine.tick(from + i * stepMs);
```

断言与期望值一个字都不许改——这是夹具的错，不是被测代码的错。实测出处：mot Task 4 报告顾虑 3（`54aabb7..7233c40`，mot 已在 `src/games/mot/` 内改正）。seqmem、gestalt、stroop 的夹具若照抄旧写法，按本条改正并在各自报告里点名。

## K-11 注册会连带弄红今日计划用例

`src/ui/pages/play.test.ts` 里有一条用例把今日计划的 `games` 写成硬编码数组，而 `play.ts` 是 `GAMES.map(g => g.id)` 建计划。**每次向 `GAMES` 追加一个游戏，这条都会变红**（stroop 注册时实测命中，`51c2c8a` 已把它改成 `['schulte', 'stroop']`）。

规定的动作：把这条用例的期望值改成**注册顺序的前 `PLAN_SIZE` 个 id**。⚠️ 本条原文（「注册后的完整 id 数组」）是错的，2026-10-20 由 M2 汇总步骤实测推翻：`scheduler.ts` 的 `PLAN_SIZE = 3` 会截断 `DayPlan.games`，所以五个游戏全注册后今日计划仍然只有 `['schulte', 'stroop', 'seqmem']`，永远不可能出现五个 id。用例本身和它上面那条「计划项必须全部来自注册表」的注释都不许动。
- **只改期望值**，不删用例、不弱化断言——这条用例的意图正是「今日计划跟随注册表」，它是 `GAME_IDS` 顺序回归的活守卫。
- 定位用 `grep -n "getPlan" src/ui/pages/play.test.ts`，不许按行号找（行号会漂）。

## S-1 共享文件的改动一律推迟到 M2 汇总步骤

`src/games/registry.ts`、`src/games/registry.test.ts`、`src/ui/styles.css` 是四份计划共写的文件。并行写手同时追加会互相覆盖，`git add` 时还会夹带别人的半成品。

规定的分工：
- 各游戏的**视图任务照旧写自己的 `view.ts` / `view.test.ts` / `index.ts`**，但**不许动 `styles.css`**：把自己那段 CSS 原样写进本报告文件的「待并入样式」小节（含选择器与注释）。
- 各游戏的**注册任务不单独提交**，由控制器的 M2 汇总步骤一次落盘：按 `GAME_IDS` 声明顺序把 5 个游戏追加进 `GAMES`，按同样顺序拼接四段 `.game-*` 样式，并同步 K-11 那条用例。
- 汇总步骤只允许出现在所有视图任务都提交之后；期间 `styles.css` 里若缺某个游戏的样式，界面会暂时难看但不影响单测——这是刻意的，别「顺手补上」。

## C-1 被截断的写手会报告不存在的哈希

派单里必须写死：「提交后运行 `git log --format='%h %s' -1`，把输出原样抄进报告，报告里的哈希只能来自这条命令」。控制器复核时永远以 `git log` 自己核对，不信回报值。实测出处：2026-10-19 三个并行写手同时报过不存在的哈希并声称工作树干净，真实情况是只落了前一个提交。

## T-1 同一目录同一时刻只允许一个写手

控制器在派单前必须 `git status --porcelain` 并看目标目录 mtime，确认没有活口。重复派单实测造成过两次损失：前一个写手把后一个的变异探针当成「外部篡改」，以及控制器 `checkout` 复原时差点覆盖真实改动。
