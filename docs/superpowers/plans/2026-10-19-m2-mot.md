# M2-3 视觉动态感知 `mot`（多目标追踪）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给 `focus-trainer` 增加第 4 个游戏 `mot`：屏幕上 N 个点做确定性运动，其中 K 个开局橙色闪烁后被隐藏身份，运动停止后用户点出这 K 个点，按命中数判分并驱动自适应档位。

**Architecture:** 四层严格分离。`rules.ts` 是纯规格（10 档参数表、几何常量、judge/summarize/formatSummary）；`physics.ts` 是纯几何与纯运动（不重叠撒点、定长步推进、碰壁反射、等质量弹性碰撞、每秒 ±30° 方向偏转、坐标→命中点的反查）；`engine.ts` 只做「相位机 + 从逻辑时间轴推导步数 + 记账」，**所有时间只来自 `start(now)` / `tick(now)` / `input(e.t)`**；`view.ts` 只做「把归一化坐标写成绝对定位 DOM 点的 `transform: translate3d(…)`，把 pointerdown 反归一化后 emit」，不用 `<canvas>`、不自建计时器。

**Tech Stack:** TypeScript 5.9.3（`strict` + `verbatimModuleSyntax`）、Vite 8.3.4、Vitest 5.0.5（**node 环境，没有 jsdom、没有 canvas API**）、零新增依赖。视图测试沿用 `src/games/schulte/view.test.ts` 的手写零依赖 DOM 桩范式。

**Spec:** `docs/superpowers/specs/2026-10-18-focus-trainer-design.md` §3.4（第 119–142 行，档位表与判定）、§5.2（第 311 行，`mot` 的 `upAfter: 2 / downAfter: 1`）、§5.8（第 355 行，触控目标 ≥ 48px）、§6（第 361 行，MOT 运动阶段帧间隔 > 50ms → `timingValid = false`）。

## Global Constraints

- 依赖锁定：TypeScript 5.9.3 `strict` + `verbatimModuleSyntax`（类型只准 `import type`）、Vitest 5.0.5 跑在 **node 环境（无 jsdom、无 `getContext`）**、fake-indexeddb 6.2.6。**本计划不新增任何依赖**，也不引入任何图形库。
- **渲染裁定：绝不用 `<canvas>`。** 运动点用绝对定位 DOM `div` + `transform: translate3d(…)` 渲染。理由：① node 测试环境里 canvas 不可用，用 canvas 等于把视图层变成不可测代码，或逼出 `vi.stubGlobal('CanvasRenderingContext2D', …)` 这种只断言「我调用过 fillRect」的空测试；② 点的数量级只有 6–16 个，DOM + `will-change: transform` 完全够用；③ 坐标真值永远在纯层（`physics.ts`），视图只做单位换算，所以「渲染」与「判定」不会因为像素对齐而分叉。
- 时钟契约（spec §4.3）：轮内计时只用 rAF 帧时间戳与 `PointerEvent.timeStamp`；`Date.now()` 只允许用于 seed、记录时间戳、日键。**禁止给时钟加负值/NaN 钳制**（M1 Task 5 裁定 N-5）。本计划里唯一的时间钳制是显示用的 `remainMs`（视图侧 `Math.max(0, …)`），任何进入 `result()`/`judge()` 的量都不钳。
- **确定性运动 = 定长步 + 逻辑时间轴，不是帧间隔累加。** `STEP_MS = 1000 / 120`（spec §3.4「固定步长 1/120 秒」）。每帧要推进的步数由 `floor((now − 阶段逻辑起点) / STEP_MS)` 推导，而**不是** `acc += dt; while (acc >= STEP)`：后者的浮点余量取决于 dt 序列，16ms 与 48ms 两种喂帧节奏在步边界附近会差一步，轨迹就不复现了。Task 4 有测试锁死这条。
- `configure(level, seed, roundNo)` 必须重置**全部**轮内状态（含 `steps / phase / rng / timingValid / 时间基准 / selections / endAt`）。SessionRunner 的 `voidCurrentRound()` 不通知引擎，作废轮能否零残留 100% 取决于这条纪律。
- `snapshot()` 返回防御拷贝（数组与新对象），视图对快照只读。**`result()` 的拷贝口径（本计划裁定，回应 M1 未决项 T40）：一律给深拷贝** —— `trials.map((t) => ({ ...t }))` 只拷顶层，而 mot 的 trial 里带 `selections` / `targetIds` 两个内部数组，必须显式 `slice()`，否则结算页一旦排序就改到了 runner 的状态。
- 输入形态只能用现成的 `InputEvent` 联合：`{ kind: 'point'; x: number; y: number; t: number }`。**不改 `src/core/types.ts`**（改联合类型 = 越界，会炸 M1 全部测试）。视图把点击**归一化到 [0,1]² 场地坐标**后再 emit，引擎用与渲染完全相同的坐标空间做命中反查，CSS 像素永远不进纯层。
- 注册顺序按 `GAME_IDS`（`'schulte' | 'stroop' | 'seqmem' | 'mot' | 'gestalt'`）：`mot` 排在 `seqmem` 之后、`gestalt` 之前。**控制器会把 `registry.ts` 与 `src/ui/styles.css` 的共享改动抽到 M2 的统一合并步骤**，所以本计划的注册 + CSS 全部放在明确标注的 Task 8，它可能被合并执行而不是独立执行。
- 测试计数纪律：计划写期望数，但**以执行者实测为准**；不得为凑数删测试或造无断言的测试。视图测试必须覆盖「emit 必带 timeStamp」「轮结束残留清除」「destroy 摘监听」三件事。
- 提交：逐文件 `git add`，禁止 `git add -A` / `.`；不碰别人的脏文件（当前工作树有其它 agent 在改 `src/ui/`、`src/games/stroop/`、`src/games/seqmem/`）。

**本 Task 定死的数字：** 10 档参数表逐格照抄 spec §3.4:127–138；`DOT_R = 0.035`、`HIT_RADIUS = 2 * DOT_R`（= 0.07）、`MIN_SPAWN_DIST = 0.09`（> `2 * DOT_R`，保证既不相切也留出手指余量）、`PROMPT_MS = 2000`、`FEEDBACK_MS = 1000`、`MAX_FRAME_INTERVAL_MS = 50`、`MAX_SPAWN_ATTEMPTS = 500`。判定公式：`h === K → pass`、`h <= K - 2 → fail`、其余 `hold`；`score01 = h / K`。

**为什么 `judgeMot` 没有 `timeMs === 0` 分支：** mot 的判分只吃命中数，不吃时长，所以 M1「同帧完成属规格缺口、不写防御钳制」的裁定在这里没有对应代码路径。`score01 = h / k` 的除数 `k` 恒 ≥ 2（`MOT_LEVELS` 里最小 K 是 2，由本 Task 的表测试锁死），因此**不写** `k === 0 ? 0 : …` 这种保护 —— 它是不可达分支，还会掩盖档位表被改坏的事故。

```tsx
// focus-trainer/src/games/mot/rules.ts
import type { Outcome, RoundRecord, RoundResult, SummaryItem } from '../../core/types';

export interface MotLevel {
  readonly dots: number;
  readonly k: number;
  readonly v: number;
  readonly durationSec: number;
}

// spec §3.4:127–138 逐格照抄，任何改动都是改判分难度，需控制器裁定。
export const MOT_LEVELS: readonly MotLevel[] = [
  { dots: 6, k: 2, v: 0.15, durationSec: 5 },
  { dots: 8, k: 2, v: 0.18, durationSec: 6 },
  { dots: 8, k: 3, v: 0.2, durationSec: 6 },
  { dots: 10, k: 3, v: 0.22, durationSec: 7 },
  { dots: 10, k: 4, v: 0.24, durationSec: 7 },
  { dots: 12, k: 4, v: 0.27, durationSec: 8 },
  { dots: 12, k: 4, v: 0.3, durationSec: 8 },
  { dots: 14, k: 5, v: 0.32, durationSec: 9 },
  { dots: 14, k: 5, v: 0.36, durationSec: 9 },
  { dots: 16, k: 5, v: 0.4, durationSec: 10 },
];

export const MOT_MAX_LEVEL = MOT_LEVELS.length;

// 几何常量：单位一律是「归一化场地边长」，与 CSS 像素无关（视图自己乘边长）。
export const DOT_R = 0.035;
// 点选容差 = 2r。有效触点直径 = 2 × HIT_RADIUS × 边长 = 0.14 × 边长；
// spec §5.8 要求触控目标 ≥ 48px ⇒ 场地边长需 ≥ 343px，真机实测见「需要执行时才能发现的事」1。
export const HIT_RADIUS = 2 * DOT_R;
// 撒点最小中心间距：2r 只是「不相切」，这里多留 0.02 让两点不会被一根手指同时盖住。
export const MIN_SPAWN_DIST = 0.09;
export const MAX_SPAWN_ATTEMPTS = 500;

export const PROMPT_MS = 2000;
export const FEEDBACK_MS = 1000;
// spec §6:361：MOT 的运动阶段任一帧间隔 > 50ms ⇒ 本轮 timingValid = false。
export const MAX_FRAME_INTERVAL_MS = 50;

export function motLevel(level: number): MotLevel {
  if (!Number.isInteger(level) || level < 1 || level > MOT_MAX_LEVEL) {
    throw new RangeError(`mot level out of range: ${level}`);
  }
  return MOT_LEVELS[level - 1];
}

export function judgeMot(r: RoundResult): { outcome: Outcome; score01: number } {
  const k = r.metrics.k;
  const h = r.metrics.hits;
  let outcome: Outcome = 'hold';
  if (h === k) outcome = 'pass';
  else if (h <= k - 2) outcome = 'fail';
  return { outcome, score01: h / k };
}

export function summarizeMot(rounds: readonly RoundRecord[]): Record<string, number> {
  const counted = rounds.filter((x) => x.counted);
  if (counted.length === 0) return { hitRate: 0, hits: 0, targets: 0, maxK: 0 };
  const hits = counted.reduce((sum, x) => sum + x.metrics.hits, 0);
  const targets = counted.reduce((sum, x) => sum + x.metrics.k, 0);
  return {
    hitRate: Math.round((hits / targets) * 10000) / 10000,
    hits,
    targets,
    maxK: Math.max(...counted.map((x) => x.metrics.k)),
  };
}

export function formatMotSummary(s: Record<string, number>): SummaryItem[] {
  return [
    { label: '命中率', value: `${Math.round(s.hitRate * 100)}%` },
    { label: '命中 / 目标', value: `${s.hits} / ${s.targets}` },
    { label: '最高目标数', value: `${s.maxK} 个` },
  ];
}
```

```tsx
// focus-trainer/src/games/mot/physics.ts
import { shuffle } from '../../core/rng';
import type { Rng } from '../../core/rng';
import { DOT_R, HIT_RADIUS, MAX_SPAWN_ATTEMPTS, MIN_SPAWN_DIST } from './rules';
import type { MotLevel } from './rules';

export interface DotState {
  readonly id: number;
  readonly x: number;
  readonly y: number;
  readonly vx: number;
  readonly vy: number;
  readonly target: boolean;
}

// rng 的调用顺序是复现性的一部分：先按 id 顺序撒位置，再抽 K 个目标下标，最后逐点取方向角。
// 任何一步换了顺序，同 (level, seed) 的轨迹就变了 —— 改动前先跑 repro 测试。
export function spawnDots(rng: Rng, lv: MotLevel): DotState[] {
  const lo = DOT_R;
  const hi = 1 - DOT_R;
  const pts: Array<{ x: number; y: number }> = [];
  for (let i = 0; i < lv.dots; i++) {
    let placed = false;
    for (let attempt = 0; attempt < MAX_SPAWN_ATTEMPTS && !placed; attempt++) {
      const x = lo + rng() * (hi - lo);
      const y = lo + rng() * (hi - lo);
      if (pts.every((p) => Math.hypot(p.x - x, p.y - y) >= MIN_SPAWN_DIST)) {
        pts.push({ x, y });
        placed = true;
      }
    }
    if (!placed) {
      throw new Error(`mot spawn failed after ${MAX_SPAWN_ATTEMPTS} attempts (dots=${lv.dots})`);
    }
  }
  const targets = new Set(shuffle(rng, pts.map((_, i) => i)).slice(0, lv.k));
  return pts.map((p, i) => {
    const angle = rng() * Math.PI * 2;
    return {
      id: i,
      x: p.x,
      y: p.y,
      vx: Math.cos(angle) * lv.v,
      vy: Math.sin(angle) * lv.v,
      target: targets.has(i),
    };
  });
}

// 数组按 id 升序遍历 + 严格 <，所以「完全同距取 id 小的」是这条实现的性质，不是巧合。
export function hitTest(dots: readonly DotState[], x: number, y: number): number | null {
  let best: number | null = null;
  let bestDist = Infinity;
  for (const d of dots) {
    const dist = Math.hypot(d.x - x, d.y - y);
    if (dist <= HIT_RADIUS && dist < bestDist) {
      best = d.id;
      bestDist = dist;
    }
  }
  return best;
}
```

**定长步的两个字面值，别踩坑：**
- `STEPS_PER_SECOND = 120`、`STEP_MS = 1000 / 120`（spec §3.4:123「固定步长 1/120 秒」）。位置积分用 `STEP_SEC = 1 / 120`。
- `frameSteps(elapsedMs)` **必须写成 `Math.floor((elapsedMs * STEPS_PER_SECOND) / 1000)`，不能写 `Math.floor(elapsedMs / STEP_MS)`**。原因：`1000 / 120 = 8.333333333333334` 是向上舍入的双精度值，`Math.floor(1000 / (1000 / 120)) === 119` 而不是 120 —— 整秒边界会少模拟一步，档位 10 的曝光时长就少 8.3ms 的运动量，而且这种错只在特 elapsed 值上出现，端到端跑根本看不出来。乘 120 再除 1000 在整数毫秒上是精确的。**本 Task 有专门一条用例锁这个字面值。**
- `frameSteps` 对负输入返回负数，**不加 `Math.max(0, …)`**（M1 裁定 N-5：时钟不写防御钳制）。上游 `while (steps < target)` 对 `target <= steps` 天然不动作，负值不会造成任何副作用；测试显式断言这个负值，防止后来者"顺手修好"它而把钳制请回来。

**运动模型的四个成分（spec §3.4:123 逐条对应）：** 匀速积分 → 碰壁**镜像反射**（`x = 2*DOT_R - x`，比「钳到边界再反向」少丢最多一步的位移）→ 等质量弹性碰撞（沿连线法线交换法向分量，`a < b` 升序单遍保证确定性）+ 位置推开 → 速率归一回 `lv.v`；每满 120 步给每个点的方向做 `±30°` 旋转（旋转矩阵保模长，所以偏转本身不会破坏「速率恒为 v」）。

```tsx
// 追加到 focus-trainer/src/games/mot/physics.ts
// 同时把 DotState 的 4 个字段声明从 readonly 改成可变（每步新建对象，对外仍按只读使用；
// 内部 resolvePair 需要原地写）。Task 2 的测试不受影响。
export interface DotState {
  id: number;
  x: number;
  y: number;
  vx: number;
  vy: number;
  target: boolean;
}

export const STEPS_PER_SECOND = 120;
export const STEP_MS = 1000 / STEPS_PER_SECOND;
export const STEP_SEC = 1 / STEPS_PER_SECOND;
export const JITTER_DEG = 30;

// 步数必须由「距阶段逻辑起点的 elapsed」推导，不能靠帧间隔累加：
// 后者的浮点余量取决于 dt 序列，16ms 与 48ms 两种节奏会在步边界差一步，轨迹就不复现。
// 另外必须是 elapsed * 120 / 1000 —— 见本 Task 开头，1000 / STEP_MS 的除法在整秒上会得 119。
// 负 elapsed 不钳制（N-5），while (steps < target) 对负 target 天然不动作。
export function frameSteps(elapsedMs: number): number {
  return Math.floor((elapsedMs * STEPS_PER_SECOND) / 1000);
}

const FIELD_LO = DOT_R;
const FIELD_HI = 1 - DOT_R;

// 几何钳制（点不能跑出场地）与时钟契约的「禁止负值/NaN 钳制」无关：后者管的是 now/dt/timeMs 这类
// 判分输入，这里管的是模拟状态必须在 [0,1]² 场地内，属于物理约束。
function clampField(p: number): number {
  return Math.min(FIELD_HI, Math.max(FIELD_LO, p));
}

function renormalize(d: DotState, speed: number): void {
  const s = Math.hypot(d.vx, d.vy);
  if (s === 0) {
    // 只有人为构造零速点才会到这里（spawnDots 恒给 |v| = speed）。确定性兜底：按 +x 方向重赋速率，
    // 不抛错也不留 NaN —— NaN 会一路污染后续所有位置，且复现测试只会看到「不相等」而说不出原因。
    d.vx = speed;
    d.vy = 0;
    return;
  }
  d.vx = (d.vx / s) * speed;
  d.vy = (d.vy / s) * speed;
}

function resolvePair(dots: DotState[], ai: number, bi: number, speed: number): void {
  const A = dots[ai];
  const B = dots[bi];
  const minDist = 2 * DOT_R;
  const dx = B.x - A.x;
  const dy = B.y - A.y;
  const dist = Math.hypot(dx, dy);
  if (dist >= minDist) return;
  // dist === 0 只可能来自人为构造；给确定的法线，避免 NaN 方向。
  const nx = dist === 0 ? 1 : dx / dist;
  const ny = dist === 0 ? 0 : dy / dist;
  const van = A.vx * nx + A.vy * ny;
  const vbn = B.vx * nx + B.vy * ny;
  if (van - vbn > 0) {
    // 等质量完全弹性碰撞 = 交换沿法线的速度分量；切向分量不动。
    const dvn = van - vbn;
    A.vx -= dvn * nx;
    A.vy -= dvn * ny;
    B.vx += dvn * nx;
    B.vy += dvn * ny;
  }
  const push = (minDist - dist) / 2 + 0.0005;
  A.x = clampField(A.x - push * nx);
  A.y = clampField(A.y - push * ny);
  B.x = clampField(B.x + push * nx);
  B.y = clampField(B.y + push * ny);
  renormalize(A, speed);
  renormalize(B, speed);
}

// 每步：积分 → 反射 → 单遍成对碰撞（a < b 升序 = 确定顺序）→ 每满 120 步做 ±30° 方向偏转。
// rng 只在偏转时消费，所以「没有碰撞的 119 步不消耗随机数」是可测的（本 Task 有用例）。
export function stepOnce(dots: readonly DotState[], rng: Rng, lv: MotLevel, stepIndex: number): DotState[] {
  const next: DotState[] = dots.map((d) => {
    let { x, y, vx, vy } = d;
    x += vx * STEP_SEC;
    y += vy * STEP_SEC;
    if (x < FIELD_LO) {
      x = 2 * FIELD_LO - x;
      vx = -vx;
    } else if (x > FIELD_HI) {
      x = 2 * FIELD_HI - x;
      vx = -vx;
    }
    if (y < FIELD_LO) {
      y = 2 * FIELD_LO - y;
      vy = -vy;
    } else if (y > FIELD_HI) {
      y = 2 * FIELD_HI - y;
      vy = -vy;
    }
    return { id: d.id, x, y, vx, vy, target: d.target };
  });
  for (let a = 0; a < next.length; a++) {
    for (let b = a + 1; b < next.length; b++) resolvePair(next, a, b, lv.v);
  }
  if ((stepIndex + 1) % STEPS_PER_SECOND === 0) {
    const rad = (JITTER_DEG * Math.PI) / 180;
    for (let i = 0; i < next.length; i++) {
      const theta = (rng() * 2 - 1) * rad;
      const cos = Math.cos(theta);
      const sin = Math.sin(theta);
      const { vx, vy } = next[i];
      next[i] = { ...next[i], vx: vx * cos - vy * sin, vy: vx * sin + vy * cos };
    }
  }
  return next;
}
```

```tsx
// focus-trainer/src/games/mot/engine.ts
import { createRng } from '../../core/rng';
import type { Rng } from '../../core/rng';
import type { InputEvent } from '../../core/types';
import { MAX_FRAME_INTERVAL_MS, MOT_LEVELS, PROMPT_MS, motLevel } from './rules';
import type { MotLevel } from './rules';
import { STEPS_PER_SECOND, frameSteps, hitTest, spawnDots, stepOnce } from './physics';
import type { DotState } from './physics';

export type MotPhase = 'prompt' | 'motion' | 'answer' | 'feedback';
export type MotMark = 'none' | 'hit' | 'wrong' | 'missed';

export interface MotDotView {
  readonly id: number;
  readonly x: number;
  readonly y: number;
  readonly target: boolean;
  readonly selected: boolean;
  readonly mark: MotMark;
}

export interface MotSnapshot {
  readonly phase: MotPhase;
  readonly dots: readonly MotDotView[];
  readonly k: number;
  readonly selectedCount: number;
  readonly remainMs: number;
  readonly simSteps: number;
  readonly timingValid: boolean;
  readonly done: boolean;
}

// 本 Task 起 MotEngine 还只是「一个类」；Task 5 补上 result() 之后才声明
// implements GameEngine<MotSnapshot>，index.ts 也才可能引用它。
export class MotEngine {
  private level = 1;
  private seed = 0;
  private lv: MotLevel = MOT_LEVELS[0];
  private rng: Rng = createRng(0);
  private dots: DotState[] = [];
  private selections: number[] = [];
  private phase: MotPhase = 'prompt';
  private startAt = 0;
  private promptEndAt = 0;
  private motionEndAt = 0;
  private now = 0;
  private lastTickAt = 0;
  private baselined = false;
  private steps = 0;
  private timingValid = true;
  private endAt: number | null = null;

  // 形参与 GameEngine.configure 逐字一致。roundNo 与舒尔特同口径：只是 SessionRunner 的记账字段，
  // mot 的题面与判分都不看它（看了就会破坏「同 (level, seed) 同轨迹」的复现契约）。
  configure(level: number, seed: number, roundNo: number): void {
    const lv = motLevel(level);
    this.level = level;
    this.seed = seed;
    this.lv = lv;
    this.rng = createRng(seed);
    this.dots = spawnDots(this.rng, lv);
    this.selections = [];
    this.phase = 'prompt';
    // 作废契约（spec §5.1）：SessionRunner.voidCurrentRound() 不通知引擎，重开轮只调 configure + start。
    // 时间基准、步数、rng、timingValid 必须在这里一起归零，否则作废轮会带着上一轮的轨迹残留开跑。
    this.startAt = 0;
    this.promptEndAt = 0;
    this.motionEndAt = 0;
    this.now = 0;
    this.lastTickAt = 0;
    this.baselined = false;
    this.steps = 0;
    this.timingValid = true;
    this.endAt = null;
    void roundNo;
  }

  start(now: number): void {
    this.startAt = now;
    this.promptEndAt = now + PROMPT_MS;
    this.motionEndAt = this.promptEndAt + this.lv.durationSec * 1000;
    this.now = now;
    this.lastTickAt = now;
    this.baselined = false;
    this.phase = 'prompt';
    this.steps = 0;
  }

  tick(now: number): void {
    if (this.endAt !== null) return;
    // 帧间隔判定用「上一帧到这一帧」的差；相位取判定时刻的旧相位（answer 之后的间隔合法）。
    const gap = now - this.lastTickAt;
    if (this.baselined && (this.phase === 'prompt' || this.phase === 'motion') && gap > MAX_FRAME_INTERVAL_MS) {
      this.timingValid = false;
    }
    this.lastTickAt = now;
    this.baselined = true;
    this.now = now;

    if (this.phase === 'prompt' && now >= this.promptEndAt) this.phase = 'motion';
    if (this.phase === 'motion') {
      // 目标步数只由「距运动起点的逻辑 elapsed」推导 ⇒ 与喂帧节奏无关，轨迹可复现。
      // 上限钉死在 D × 120：跨过运动结束点的那一帧最坏溢出 15ms，不加限制就会多模拟一步，
      // 曝光时长就不再等于档位表的 D 秒（这是规格量，不是时钟量，所以这里必须有上限）。
      const target = Math.min(
        frameSteps(now - this.promptEndAt),
        this.lv.durationSec * STEPS_PER_SECOND,
      );
      while (this.steps < target) {
        this.dots = stepOnce(this.dots, this.rng, this.lv, this.steps);
        this.steps += 1;
      }
      if (now >= this.motionEndAt) this.phase = 'answer';
    }
  }

  input(e: InputEvent): void {
    if (e.kind !== 'point') return;
    if (this.phase !== 'answer') return; // 提示与运动阶段拒绝一切点选
    if (this.endAt !== null) return;
    const id = hitTest(this.dots, e.x, e.y);
    if (id === null) return; // 容差外的空点：忽略。spec §3.4 只有「命中/误选」，没有误点罚分
    const i = this.selections.indexOf(id);
    if (i >= 0) this.selections.splice(i, 1); // 「再点一次取消」
    else this.selections.push(id);
  }

  snapshot(): MotSnapshot {
    const reveal = this.phase === 'prompt' || this.phase === 'feedback';
    return {
      phase: this.phase,
      dots: this.dots.map((d) => ({
        id: d.id,
        x: d.x,
        y: d.y,
        // 身份只在提示与反馈阶段出快照。若在运动/作答阶段把 target 写进 DOM，
        // 读一次 class 就能作弊，判分当场失效 —— 这条泄漏不会有类型错误。
        target: reveal ? d.target : false,
        selected: this.selections.includes(d.id),
        mark: 'none' as MotMark,
      })),
      k: this.lv.k,
      selectedCount: this.selections.length,
      remainMs: this.remainMs(),
      simSteps: this.steps,
      timingValid: this.timingValid,
      done: this.endAt !== null,
    };
  }

  isDone(): boolean {
    return this.endAt !== null;
  }

  // 原始差值，可以为负（tick 落后于阶段边界是常态）。视图显示时才 Math.max(0, …) ——
  // 判分路径上的任何时间量都不钳（M1 裁定 N-5）。
  private remainMs(): number {
    if (this.phase === 'prompt') return this.promptEndAt - this.now;
    if (this.phase === 'motion') return this.motionEndAt - this.now;
    return 0; // answer 不限时；feedback 分支由 Task 5 加
  }
}
```

- 选满 `lv.k` 个的那一刻 = 提交：`submitAt = e.t`（唯一合法时间源是 `PointerEvent.timeStamp`）、`phase = 'feedback'`、`feedbackEndAt = submitAt + FEEDBACK_MS`。没有「提交」按钮，也没有任何 `setTimeout`。

```tsx
    return {
      phase: this.phase,
      dots: this.dots.map((d) => ({
        id: d.id,

    return d.target ? 'missed' : 'none';

          targetIds: targetIds.slice(),

        simSteps: this.steps,
        motionMs: this.lv.durationSec * 1000,
        answerMs,
      },
      timingValid: this.timingValid,
    };
```

```tsx
// focus-trainer/src/games/mot/view.ts
import type { GameView, InputEvent } from '../../core/types';
import type { MotSnapshot } from './engine';

const FIELD_CLASS = 'mot-field';

export function createMotView(host: HTMLElement, emit: (e: InputEvent) => void): GameView<MotSnapshot> {
  const root = document.createElement('div');
  root.className = 'mot';
  const info = document.createElement('div');
  info.className = 'mot-info';
  const field = document.createElement('div');
  field.className = FIELD_CLASS;
  root.append(info, field);
  host.append(root);

  // 只在点数变化时重建：每帧 replaceChildren 会打断 transform 的合成层连续性（点会抖），
  // 并把 16 个节点的创建摊到每秒 60 帧上。
  let dots: Stub[] = [];
  type Stub = ReturnType<typeof document.createElement>;

  const onDown = (ev: PointerEvent): void => {
    const rect = field.getBoundingClientRect();
    // 边长 0 = 场地还没布局（或父级 display:none）。除以 0 得到 Infinity/NaN，
    // 它会一路进 hitTest 并静默判空。这是几何守卫，与时钟契约禁的「负值/NaN 钳制」无关。
    if (!(rect.width > 0) || !(rect.height > 0)) return;
    ev.preventDefault();
    emit({
      kind: 'point',
      x: (ev.clientX - rect.left) / rect.width,
      y: (ev.clientY - rect.top) / rect.height,
      t: ev.timeStamp, // 与 rAF 同域；Task 4 的 startAt / submitAt 都吃它，绝不 Date.now()
    });
  };
  field.addEventListener('pointerdown', onDown);

  const infoText = (s: MotSnapshot): string => {
    // 唯一允许钳 0 的地方：显示量。判分路径上的时间（engine 的 remainMs / answerMs）都是原始差值。
    const remain = Math.max(0, s.remainMs) / 1000;
    if (s.phase === 'prompt') return `盯住 ${s.k} 个橙色点　${remain.toFixed(1)} 秒`;
    if (s.phase === 'motion') return `追踪目标　剩余 ${remain.toFixed(1)} 秒`;
    if (s.phase === 'answer') return `点出 ${s.k} 个目标　已选 ${s.selectedCount}`;
    return `命中 ${s.dots.filter((d) => d.mark === 'hit').length} / ${s.k}`;
  };

  return {
    render(s) {
      if (s.dots.length !== dots.length) {
        dots = s.dots.map(() => {
          const el = document.createElement('div');
          el.className = 'mot-dot';
          return el;
        });
        field.replaceChildren(...dots);
      }
      const side = field.getBoundingClientRect().width;
      const phaseClass = `${FIELD_CLASS} ${s.phase}`;
      if (field.className !== phaseClass) field.className = phaseClass;
      s.dots.forEach((d, i) => {
        const el = dots[i];
        el.className = ['mot-dot', d.target && 'target', d.selected && 'sel', d.mark !== 'none' && d.mark]
          .filter(Boolean)
          .join(' ');
        el.style.transform = `translate3d(${d.x * side}px, ${d.y * side}px, 0)`;
      });
      info.textContent = infoText(s);
    },
    destroy() {
      field.removeEventListener('pointerdown', onDown);
      root.remove();
      dots = [];
    },
  };
}
```

> `let dots: Stub[]` + `type Stub = ReturnType<typeof document.createElement>` 这两行如果执行者觉得绕，可以写成 `let dots: HTMLElement[] = []`；本仓 `src/games/schulte/view.ts` 用的正是 `HTMLElement[]`。**两种都行，但必须只有一种出现在最终代码里**，且 `document.createElement('div')` 的返回值赋给 `HTMLElement` 时若 TS 报 `HTMLDivElement` 不兼容，就用 `HTMLElement[]`（`createElement` 的重载返回 `HTMLDivElement`，赋给 `HTMLElement[]` 是加宽，合法）。

```tsx
const enginePhase = (r: SessionRunner): MotPhase | null =>
  r.snapshot().phase === 'playing' ? (r.engine.snapshot() as MotSnapshot).phase : null;

function tickUntil(r: SessionRunner, from: number, pred: () => boolean): number {
  let t = from;
  for (let i = 0; i < 4000 && !pred(); i++) {
    t += FRAME;
    r.tick(t);

  expect(pred()).toBe(true); // 驱动器没走到条件就是测试自身失效，绝不能静默返回

// 玩完「当前已开的那一轮」，返回轮结束（引擎 isDone、runner 进 between/finished）后的时刻。

function playRound(r: SessionRunner, from: number, hitCount: number, gap: number | null): number {
  let t = from;
  const s0 = r.engine.snapshot() as MotSnapshot; // 此刻是 prompt 相位，能看到目标身份
  const k = s0.k;
  const targets = s0.dots.filter((d) => d.target).map((d) => d.id);

    t += FRAME;
    r.tick(t);
    t += FRAME;
    r.tick(t);
    t += gap; // 第三个帧间隔：远超 50ms ⇒ 作废（首帧只建基准，不会误伤）
    r.tick(t);

  t = tickUntil(r, t, () => enginePhase(r) === 'answer');

  const others = frozen.dots.map((d) => d.id).filter((id) => !targets.includes(id));
  const hits = Math.min(hitCount, k);
  const chosen = [...targets.slice(0, hits), ...others.slice(0, k - hits)];
  for (const id of chosen) {
    const d = frozen.dots.find((x) => x.id === id) as MotDotView;
    t += FRAME;
    r.input({ kind: 'point', x: d.x, y: d.y, t });
  }
  return tickUntil(r, t, () => r.snapshot().phase !== 'playing');
```

## 需要执行时才能发现的事

1. **场地实际边长**：`.mot-field` 的渲染宽度由训练页容器决定（M1 的 `.game-area` 宽度 + 页面 padding）。有效触点直径 = `0.14 × 边长`，要 ≥ 48px 就得边长 ≥ 343px。真机上若小于此值，**不要私自改 `HIT_RADIUS`**（改容差 = 改判分难度），报给控制器裁定。
2. **rAF 泵与 `roundBreak: 'auto'` 的衔接**：`AUTO_BREAK_MS = 600`（`session.ts:19`）是共享的，加在引擎自身的 1000ms 反馈之后，一轮到下一轮的空白总时长 ≈ 1.6s。真机上觉得拖沓就报控制器，别改 `session.ts`。
3. **`will-change: transform` 的实测帧率**：16 个点 + 每秒 120 次模拟（每帧 1–8 步）在任何中端机上都不是瓶颈，但 `getBoundingClientRect()` 每帧一次会触发 layout read；若实测掉帧，可把边长缓存到 `resize` 事件上 —— 这属于视图内部优化，不影响任何数字。
4. **首帧基线**：`start(now)` 的时刻可能来自点击事件而非 rAF 帧，因此第一个 tick 只建立基准、不判帧间隔（Task 4 有测试）。真机上如果倒计时层切到游戏区的第一个 rAF 帧间隔天生 > 50ms，这条设计正好救场；若仍然大量 invalid，说明 UI 层的泵没接上，是 UI 的 bug。
5. **档位 10（16 点 / K=5 / v=0.40）的手感**：`MIN_SPAWN_DIST = 0.09` 与 500 次重采样的接受率必须在真机上验证撒点不失败；纯层测试用 40 个种子扫描（Task 2），真机若出现 `mot spawn failed` 立刻上报，不要加大容差掩盖。
